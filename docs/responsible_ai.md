# Responsible AI

This document describes the responsible-AI safeguards built into the
Insurance Claims Risk & Severity Platform, covering both the predictive
severity model and the GenAI explanation layer.

## Scope and intended use

This project is a **decision-support** tool for insurance claims analysts.
It predicts a *severity score* for a claim and surfaces contributing
factors and a plain-language explanation. It is explicitly **not**:

- A coverage determination system
- A legal or liability conclusion engine
- A fraud detection or fraud determination system
- A medical diagnosis tool
- An automated payout/claims-approval system

Any of these decisions must be made by a qualified human claims
professional, using this tool's output as one input among several.

## Model risk and limitations

- **Historical bias**: the model is trained on historical claims data and
  will reproduce any patterns (including biases) present in that data.
  Predictions should be treated as statistical associations, not causal
  or normative judgments about any claimant.
- **Feature importance is not causation**: "top factors" reported by the
  model reflect learned associations, not proof that a factor caused the
  outcome.
- **Data quality dependency**: predictions are only as reliable as the
  input data. The pipeline surfaces data-quality warnings
  (`src/validate.py`) so low-confidence predictions can be flagged for
  human review.
- **Distribution shift**: `src/monitoring.py` implements lightweight drift
  heuristics comparing live prediction/feature distributions to a
  reference baseline, to help detect when the model may no longer be
  well-calibrated for incoming claims.

## GenAI explanation-layer safeguards (`src/genai.py`)

The GenAI layer (`explain_claim`, `build_explanation_prompt`) is
deliberately constrained:

1. **Deterministic by default.** No LLM API keys or network calls are
   required to run this project. Explanations are generated by a
   rule-based, fully deterministic function unless a provider is
   explicitly wired in via the `GENAI_PROVIDER` environment variable
   (left unimplemented in this open-source build).
2. **Structured, bounded output.** `explain_claim` returns a
   `ClaimExplanation` dataclass with a fixed set of fields (predicted
   severity, baseline, risk tier, contributing factors, data-quality
   warnings, confidence note, human-review recommendation, and
   disclaimer). There is intentionally no field for coverage, legal
   conclusions, fraud determinations, or payout amounts.
3. **Prompt-injection resistance.** Any free-text claim fields that are
   interpolated into an LLM prompt are passed through
   `_sanitize_claim_text`, which truncates long inputs and redacts
   phrases commonly used in instruction-injection attempts (for example
   "ignore previous instructions", "system:", "you are now", "admin
   override"). Claim data is always treated as untrusted data, never as
   instructions, and the system prompt explicitly states this.
4. **Mandatory disclaimers.** Every `ClaimExplanation` includes a
   human-review recommendation and a disclaimer that the system does not
   determine coverage, legal liability, fraud, medical outcomes, or
   payout amounts.

## Operational safeguards

- **No secrets or PII in the repository.** The repository never commits
  credentials, API keys, real claims data, or model binaries. Smoke
  tests use small, synthetic data (`data/smoke_sample.csv`).
- **CI enforcement.** Linting and the full test suite (including the
  safety-contract tests in `tests/test_genai.py`) run on every push via
  GitHub Actions, so regressions in these safeguards are caught
  automatically.
- **Human-in-the-loop.** The FastAPI service (`src/api.py`) and CLI
  outputs are designed to support, not replace, review by a claims
  professional.

## Reporting concerns

If you identify a way this system could be used to make an automated
coverage, legal, fraud, or payout decision without human review, or a way
the GenAI layer could be manipulated into violating its safety contract,
please open an issue describing the scenario.
